# FPS-LAN — Game Design

## Game Identity

A fast, compact LAN FPS focused on close and medium-range combat.

The game should be:
- easy to understand
- fast to enter
- responsive
- chaotic when desired
- mechanically expressive
- fun with a small group of friends

Do not aim for military simulation.

## First Game Mode

Free For All / Deathmatch.

Every player fights independently.

Required match information:
- kills
- deaths
- scoreboard

## Player Movement — MVP

- WASD
- mouse look
- sprint
- jump
- gravity
- collision

Movement should feel responsive and slightly arcade-like.

## Future Movement

Possible later mechanics:
- double jump
- slide
- wall jump
- wall run
- dash
- air control
- bunny hopping
- vaulting
- grapple or mobility abilities

These should be added incrementally and only after the base movement is fun.

## Combat — MVP

Start with one automatic rifle.

Required:
- shooting
- fire rate
- magazine
- reload
- ammunition
- recoil
- damage
- headshots
- hit feedback
- muzzle flash
- impact effects
- death

Future weapons:
- pistol
- SMG
- shotgun
- sniper
- melee
- special weapons

## Map Philosophy

Maps should be small and designed around encounters.

Use:
- cover
- short/medium sightlines
- alternate routes
- controlled verticality
- corners
- flanking routes
- multiple spawn areas

Avoid:
- huge empty spaces
- extremely long sightlines
- confusing layouts
- spawn traps
- excessive walking between fights

The first map can use simple modular/prototype geometry, but it should already have intentional composition and visual identity.

## Game Feel

Prioritize:
- responsive input
- satisfying weapon response
- hit markers
- hit sounds
- recoil
- muzzle flash
- impact particles
- subtle camera feedback
- clear death feedback

Do not overload the screen with effects.
